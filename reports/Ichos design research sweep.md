# Borrow Windows' tokens, copy agents' guardrails

The sweep supports Ichos's planned direction. One sidebar, one composer, windows beside the chat, dockable panels and an assistant that shrinks to a notch is now the standard layout across the products studied. It is not an experiment. **Claude Code Desktop, Cursor 3.1 and VS Code all ship panes that drag, resize, pop out to their own OS window and dock back**, and Copilot on Windows is testing float / picture-in-picture / dock-left / dock-right states for the whole app. So the layout itself will not set Ichos apart. Three things will: native-feeling visuals, a careful permission layer for agents, and voice routines that do not misfire. On visuals, the strongest recommendation is to rebase `docs/DESIGN.md` §2 on the **Windows 11 (WinUI) dark resource set**, a #202020 base with *translucent white* fills, text at 100 / 77 / 53 / 36.5 % white, 4 px control radius and 8 px overlay radius, and a 14/20 body size. Fluent web tokens cover spacing, shadow and motion, and IBM Carbon's "AI presence" recipe marks AI-driven surfaces. Several existing choices conflict with this, and the last section tabulates them. The most consequential are 13 px body text, 28 px hit targets, an accent-coloured focus ring, and a `--text-dim` that measures **6.0:1 on `surface-2`, short of DESIGN.md's own 7:1 target**. For agents, the products have converged on scoped approval cards (once / this task / always / deny), capability tiers fixed by category, a short list of actions that always ask, and always-visible Take control / Pause / Stop. For voice, the evidence says to make typed text the source of truth for each phrase and to require the wake word by default. "Open up", one of the owner's examples, is exactly the kind of short common phrase that fires during ordinary speech. Two implementation traps stand out. **Ctrl+Alt+Space, the notch hotkey proposed in the notes, is already Claude Desktop's quick-chat key on Windows.** And Windows sends no event when a full-screen app starts, so the notch has to poll to stay out of games.

## Windows 11's dark resources beat a hand-built grey ladder

Every mature dark theme has the same structure. There is a near-black base, three or four raised steps, text at roughly 95 / 75 / 55 / 35 % luminance, and borders drawn as low-alpha white. The bases cluster tightly: Primer #0D1117, Radix #111111, Carbon #161616, Atlassian #1F1F21, WinUI #202020 and Fluent web #292929 ([Primer](https://github.com/primer/primitives/blob/main/src/tokens/base/color/dark/dark.json5); [Radix](https://github.com/radix-ui/colors/blob/main/src/dark.ts); [Carbon g100](https://cdn.jsdelivr.net/npm/@carbon/themes/src/g100.js); [Atlassian dark](https://unpkg.com/@atlaskit/tokens/dist/esm/artifacts/themes/atlassian-dark.js); [wpfui Dark.xaml](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Resources/Theme/Dark.xaml)). Where they differ is in *how* the ladder is built. Microsoft runs two dark systems. Fluent 2 web uses an opaque grey ramp ([fluentui darkColor.ts](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/alias/darkColor.ts)). Windows 11 itself paints #202020 and draws controls, cards and text as **translucent white over that base**: control fill 5.9 % white, hover 8.2 %, pressed 3.1 %, card 5.1 %, divider 8.2 %. That base is designed to sit on Mica ([wpfui Dark.xaml](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Resources/Theme/Dark.xaml)). Ichos is Windows-first and dark-first, so the translucent approach is the better fit. One token set then works on a solid window, on Mica when the shell enables it, and inside floating or popped-out panels whose background differs from the main window. An opaque ladder like DESIGN.md's `#141418 / #1c1c21 / #232329 / #2c2c33` needs separate values for each of those contexts. Microsoft's Mica rules add several constraints. Apply the material once per app, only to long-lived window backdrops and never to a UI element. Expect it to fall back to solid #202020 when the window is inactive, transparency is off or Battery Saver is on. Extend it into a transparent custom title bar ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)).

The values below come from the WinUI dark resources for surfaces, text, fills and strokes, and from Fluent web for brand, shadow and motion. One caveat applies: the WinUI values were read from a faithful third-party port (WPF UI), because the original microsoft-ui-xaml file had moved. Only `TextFillColorPrimary` was confirmed directly against Microsoft's page ([XAML theme resources](https://learn.microsoft.com/windows/apps/design/style/xaml-theme-resources)). I computed the contrast figures for this report (WCAG relative luminance, alpha blended over the named base).

The accent rule is structural, not a hex value. On dark, accent *text and strokes* use a light step and *filled* accent buttons use a mid step with white text. Fluent pairs brand[100] with brand[70] this way, and Material 3 does the same with tone 80 against container tone 30 ([darkColor.ts](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/alias/darkColor.ts); [M3 color spec](https://github.com/material-foundation/material-color-utilities/blob/main/typescript/dynamiccolor/color_spec_2021.ts)). If the owner picks a non-blue signature, keep that step structure and re-verify contrast. The blue values above are Fluent's defaults and are only placeholders.

Type should use the **Windows 11 Segoe UI Variable ramp as published**: Caption 12/16, Body 14/20, Body Strong 14/20 Semibold, Body Large 18/24, Subtitle 20/28, Title 28/36, Title Large 40/52, Display 68/92. Use only Regular (400) and Semibold (600). Microsoft states that "Bold and Italic styles are not part of the Windows type ramp" and that the minimum sizes are 14 px Semibold and 12 px Regular ([Typography in Windows](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)). Geometry follows the same source: **4 px for in-page controls, 8 px for windows, flyouts and dialogs, and 0 px for snapped or maximised windows and for edges that meet** ([Geometry in Windows 11](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/geometry)). Fluent's 2XLarge 12 px is the natural step for the composer and chat bubbles ([borderRadius.ts](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/global/borderRadius.ts)). Spacing is Fluent's 2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32 ladder ([spacings.ts](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/global/spacings.ts)). Windows layout gaps are 8 between buttons, 12 between control and label, and 16 from surface edge to text ([Content layout](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics)). Targets are **40 × 40 standard and 32 × 32 compact for pointer-dense chrome** ([Targeting](https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-targeting)). Elevation uses Fluent's two-layer shadows, with an ambient layer at rgba(0,0,0,.24) and a key layer at .28 in dark: shadow2 for controls, 8 for cards, 28 for flyouts and 64 for dialogs ([shadows.ts](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/utils/shadows.ts)). Atlassian adds a 1 px light ring (#BDBDBD1F) to dark overlays so they separate from dark surfaces. Floating and popped-out Ichos panels need exactly that ([Atlassian dark](https://unpkg.com/@atlaskit/tokens/dist/esm/artifacts/themes/atlassian-dark.js)).

Fluent, Material and Carbon agree on motion. Micro-interactions take 50–150 ms, standard transitions 200–300 ms and large or overlay moves 300–500 ms, with deceleration on enter and acceleration on exit ([Fluent durations](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/global/durations.ts); [Fluent curves](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/global/curves.ts); [M3 Motion](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md); [@carbon/motion](https://cdn.jsdelivr.net/npm/@carbon/motion/src/index.js)). Carbon's split between *productive* and *expressive* motion maps cleanly onto Ichos. Chrome, docking and menus use productive curves (Fluent DecelerateMid `cubic-bezier(0,0,0,1)` in, AccelerateMid `cubic-bezier(1,0,1,1)` out). Springs are reserved for moments when the AI is present, such as the notch expanding or a window an agent opened sliding in. M3's DefaultSpatial (damping 0.9, stiffness 700) and DefaultEffects (1, 1600) are ready-made values for those. Atlassian's Rovo guidance sets the right tone: AI expression should be "invisible until needed, present while working, fully expressive when AI is front and center" ([About Rovo UI](https://atlassian.design/rovo-ui/about-rovo-ui)).

Focus should look like Windows: **a 2 px white outer ring over a 1 px 70 %-black inner ring with a 1 px margin**, shown only on `:focus-visible` ([Visual feedback](https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-visualfeedback); [wpfui Dark.xaml](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Resources/Theme/Dark.xaml)). Carbon uses the same white-plus-inset double ring ([Carbon g100](https://cdn.jsdelivr.net/npm/@carbon/themes/src/g100.js)). A neutral ring stays visible on any accent fill, and it stops the accent from carrying two meanings, focus and selection. DESIGN.md §2 currently gives it both. For token names, follow WinUI's role-first pattern in Ichos's own namespace: `--ichos-{category}-{role}[-{variant}][-{state}]`, sitting on top of a primitive layer that only semantic tokens may reference ([fluentui alias tokens](https://github.com/microsoft/fluentui/blob/master/packages/tokens/src/alias/darkColor.ts); [Primer functional tokens](https://github.com/primer/primitives/tree/main/src/tokens/functional/color)). Build the light theme by mapping each name to Fluent `webLightTheme` or WinUI Light values. Do not invert the dark values. Inverted translucent-white fills turn into translucent-black fills with different perceived contrast.

## A five-control composer and a five-destination sidebar

The consumer chat products have moved every mode and tool switch into the composer and stripped the sidebar down to navigation. Gemini selects Canvas and Deep Think from the prompt bar and labels models by tier ("Fast", "Thinking", "Pro") ([Gemini release notes](https://gemini.google/release-notes/)). DeepSeek has two toggles, DeepThink and Search, next to the field ([LearnPrompting](https://learnprompting.org/blog/guide-deepseek-chatbot)). Claude Code Desktop sets environment, folder, model and permission mode from the prompt area, and its "+" holds attachments, skills, connectors and plugins ([Claude Code Desktop](https://code.claude.com/docs/en/desktop)). The typical composer has **three to six visible controls**: [+] [mode chip] … [model tier] [mic]. Everything else sits behind "+". The live audit in DESIGN_FIX_PLAN.md found about 20 controls on the current chat sheet, so this convergence is the main fix. Two refinements carry over directly. First, label local models by capability tier with the file name second, and remove providers marked "(no key)" from the picker. Second, add a context/usage ring next to the model picker that opens a breakdown and a **Compact** action ([Claude Code Desktop](https://code.claude.com/docs/en/desktop); [VS Code chat sessions](https://code.visualstudio.com/docs/chat/chat-sessions)). Microsoft 365 Copilot's "prompt surface", which grows and reveals file or visual options as the prompt implies them, is a good way to keep the resting composer small ([Engadget](https://engadget.com/2183246/microsoft-debuts-a-more-buttoned-up-look-for-copilot)). The "@" mention bridges chat and windows. Le Chat and Poe summon agents with "@", and Krea's Seedance Studio attaches saved reference "Elements" the same way ([TechJack](https://techjacksolutions.com/ai-tools/mistral/how-to-use-mistral/); [Krea release notes](https://www.krea.ai/release-notes)). In Ichos, one "@" picker should reach sub-agents, open windows and saved assets (characters, styles, worlds).

Sidebars converge on New chat, with temporary or incognito chat one click away, then Search, then **three to five** fixed destinations, then Recents with pinned items on top. Notion's new sidebar stops at five tabs. It also marks a finished background AI answer with a blue unread dot, and the row menu offers rename / icon / delete ([Notion sidebar](https://www.notion.com/help/sidebar)). Gemini puts a Temporary Chat icon directly beside New Chat ([Gemini release notes](https://gemini.google/release-notes/)). VS Code shows sessions as active-only by default, lets you drag items into a Pinned section, and labels archive as **"Mark as Done"** ([VS Code chat sessions](https://code.visualstudio.com/docs/chat/chat-sessions)). DESIGN.md allows "≤ 7 pinned destinations". The evidence points lower: five, with everything else in More and Ctrl+K. The unread dot needs one clear meaning. The live audit found a "●" on 21 of 32 tabs, which means it currently signals nothing.

Three steering patterns from coding agents suit a general assistant. Users can **queue a correction while the agent runs without stopping it**, with a stop button and Esc kept for real interrupts. A **transcript verbosity switch** offers Normal (tool calls folded into summaries), Thinking, and Verbose (every call). A **side chat** (Ctrl+;) asks a question with the session's context but keeps it out of the main thread ([Claude Code Desktop](https://code.claude.com/docs/en/desktop)). Long thinking should end in a notification, not a spinner the user has to watch, as with Gemini Deep Think ([Gemini release notes](https://gemini.google/release-notes/)).

### Windows opened by chat need one toolbar, one version control and a visible recipe

Every side-by-side output surface uses a small top toolbar. ChatGPT Canvas steps through versions with arrows, has "Show changes" for a diff, and offers copy, share and download ([OpenAI Help](https://help.openai.com/en/articles/9930697-what-is-the-canvas-feature-in-chatgpt-and-how-do-i-use-it)). Claude Artifacts adds Preview/Code tabs, though that is documented only by third-party guides ([ClickUp](https://clickup.com/blog/claude-artifacts/)). Copilot now opens links in a side pane, **saves those tabs with the conversation**, and reads them only with permission ([Windows Insider blog](https://blogs.windows.com/windows-insider/2026/03/04/copilot-app-on-windows-opening-web-links-alongside-your-conversations-begins-rolling-out-to-windows-insiders/)). That confirms WINDOWS_IN_CHAT_PLAN.md's rule that a window belongs to the chat that opened it. The creative tools add depth. Ideogram Studio keeps a **bottom version strip**: every run adds a thumbnail, ←/→ switches between them, Undo also steps back, and "+" duplicates the current version ([Ideogram Studio](https://docs.ideogram.ai/edit/studio)). Midjourney uses a fixed per-result action set (Vary subtle/strong, Upscale, Remix…). Users can surface hidden actions through "More options", so the default set stays short ([Midjourney Variations](https://docs.midjourney.com/docs/variations)). Grok Imagine shows **four parallel variants** with "Generate More" and "Think Harder" ([Alarcon guide](https://christopheralarcon.com/blog/how-to-use-grok)). Krea runs one prompt across several models side by side and **shows estimated cost before every run** ([Krea release notes](https://www.krea.ai/release-notes)). Sequential versions and parallel variants should share one control: a "‹ 2/3 ›" switcher for history and a 1–4 grid for variants. The cost estimate should become a local "≈ 40 s · 6 GB VRAM" chip, which is the honest figure for a local-first app.

The Ideogram Studio layout is a near-direct template for the Draw window. Tools sit at the left edge. A right panel changes with the selection and holds Layers. The version strip runs along the bottom, zoom sits bottom-right, Exit top-left and Export top-right. Unavailable options are greyed out rather than hidden ([Ideogram Studio](https://docs.ideogram.ai/edit/studio)). When an agent changes a pinned tab, Figma Make's pattern applies: **stage the edits above the prompt and wait for Apply** ([Figma help](https://help.figma.com/hc/en-us/articles/42009840449175)). Carbon adds a related rule: when a user edits AI-suggested content it loses its AI styling, and a **revert-to-AI** control appears ([Carbon for AI](https://carbondesignsystem.com/guidelines/carbon-for-ai/)). For DESIGN.md §6 ("design your own tab"), a node canvas with a "/" Spotlight palette and per-node Run (Freepik Spaces, Runway Workflows) is the power-user form. Reviews call Freepik Spaces "overwhelming for beginners", though ([framia review](https://framia.converge.ai/it/blog/freepik-review)). So the Stitch-style prompt flow should stay the entry point, with a node view as an advanced option.

## Docking is a solved library problem; layout stability is the real risk

VS Code and JetBrains share a vocabulary Ichos can copy directly. VS Code gives each view a home region, and you move it by drag, by a "Move View" / "Move Focused View" command, or from the context menu. There is a per-view **"Reset Location"**, a global "Restore Defaults", and floating windows with **Always on Top** and **Compact Mode** in their title bar ([VS Code custom layout](https://code.visualstudio.com/docs/configure/custom-layout)). JetBrains adds per-panel view modes (Dock Pinned, Dock Unpinned, Undock, Float, Window) and saves the whole arrangement as a **named layout** ([IntelliJ viewing modes](https://www.jetbrains.com/help/idea/viewing-modes.html)). WINDOWS_IN_CHAT_PLAN.md §B already covers most of this: the Move-to menu, drag, voice, presets and reset. It is missing an explicit "unpinned / auto-hide" mode, which is useful for the sidebar and Status on small screens, and a per-panel reset next to the global one.

Among React libraries, **dockview is the only one with floating groups, popout windows and JSON serialisation (`toJSON`/`fromJSON`) built in**, and its core has zero runtime dependencies ([dockview.dev](https://dockview.dev/); [GitHub dockview](https://github.com/mathuo/dockview)). Three caveats apply. "Everything is MIT except `dockview-enterprise`", so pin a version and confirm no needed feature sits in the paid tier. The React wrapper renders at zero height unless its container has an explicit height. And the README says nothing about keyboard or ARIA support ([GitHub dockview](https://github.com/mathuo/dockview)). FlexLayout is the fallback: React-only, MIT and actively released, though I did not confirm its float/popout support ([npm flexlayout-react](https://www.npmjs.com/package/flexlayout-react)). react-resizable-panels is still the right primitive for splits *inside* a panel ([npm](https://www.npmjs.com/package/react-resizable-panels)). Hide the library behind a thin `layoutService.ts` so it can be swapped. Build the keyboard path yourself: a "Move focused panel…" quick-pick, because drag alone is not accessible. Version every saved preset with a schema number and a migrator. On any `fromJSON` failure, fall back to the default layout with a toast, and keep a tray item and a `--reset-layout` flag as escape hatches. Popouts are separate documents, so state, styles and event buses must survive them, and `window.open` must be intercepted in the desktop shell.

The cautionary evidence is about stability, not features. Cursor 2.0 forced a new agent layout on existing users and drew backlash, and its panes resized themselves whenever users switched agents ([Cursor forum](https://forum.cursor.com/t/cursor-2-0-agents-view-whats-the-point/140094); [resize bug](https://forum.cursor.com/t/automatic-resizing-each-time-i-switch-agents-on-the-agents-view/143562/2)). Notebookcheck counts Copilot's docked-sidebar reversal as its **"sixth UI redesign in two years"** ([Notebookcheck](https://notebookcheck.net/Windows-11-Microsoft-backpedals-on-Copilot-decision.1306140.0.html)). Users also complained that Cursor 3's Agents Window ignores the app theme ([Cursor forum](https://forum.cursor.com/t/cursor-3-agents-window/156509)). Every popped-out or floating Ichos panel must read the same tokens. When the window narrows, title-bar buttons should collapse into a ⋮ menu, as in Claude Code Desktop and Lovable ([Claude Code Desktop](https://code.claude.com/docs/en/desktop); [Lovable editor](https://docs.lovable.dev/features/projects/editor)).

### The notch should be its own tiny window that never steals focus

Apple's Dynamic Island defines the state model the notch should copy: a **minimal** bubble, a **compact** view and an **expanded** card opened by press-and-hold ([ActivityKit](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities.md)). The plan's 380 × 32 collapsed and 380 × 196 expanded sizes fit this. The voice research adds states the plan lacks: *armed* (wake detection only), *matching*, *confirming*, *running n/m*, *muted*, *interrupted*, and a brief *alert*. On Windows the hard part is not drawing the pill. It is the window behaviour around it. Electron's `setIgnoreMouseEvents(true, {forward: true})` still forwards mouse moves on Windows, so hover works on a click-through overlay ([Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)). Tauri's equivalent drops JS mouse events unless the window is focused, and child webviews have failed to click through at all ([tauri#9250](https://github.com/tauri-apps/tauri/issues/9250); [tauri#11461](https://github.com/tauri-apps/tauri/issues/11461)). The robust design avoids click-through altogether. **Make the native window exactly the pill's size and resize it per state.** Expand on a wake phrase *without* activating the window, and take focus only on a click or the hotkey. The plan's step 8 (the desktop-level notch) should adopt this from the start.

Two Windows specifics need code. First, Windows sends **no notification when a full-screen app starts or stops**, so the notch must poll `SHQueryUserNotificationState` and hide unless it returns `QUNS_ACCEPTS_NOTIFICATIONS` ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate)). The Python backend can do this every few seconds. Second, the hotkey. ChatGPT for Windows uses Alt+Space, Gemini on Windows uses Alt+Space, PowerToys Command Palette uses Win+Alt+Space, and **Claude Desktop on Windows uses Ctrl+Alt+Space** ([OpenAI Help](https://help.openai.com/en/articles/9982051); [Gemini release notes](https://gemini.google/release-notes/); [Microsoft Learn](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/overview); [anthropics/claude-code #59400](https://github.com/anthropics/claude-code/issues/59400)). A registered hotkey fails silently when another app already holds it ([OpenAI Help](https://help.openai.com/en/articles/9982051)). The owner runs Claude Desktop, so Ichos's default must avoid that whole family. It must also detect a failed registration and offer a rebind. A top-centre pill also sits where the Windows 11 Snap bar appears during window drags, so it should shrink or go click-through while a drag is in progress. The licence pitfall: boring.notch, the best open reference, is **GPL-3.0**, so read it but do not copy its code ([GitHub boring.notch](https://github.com/TheBoredTeam/boring.notch)).

## Agents earn window access through scoped, visible, revocable grants

Coding agents have the most mature permission UX, and it transfers almost unchanged to "sub-agents ask before opening or driving windows". Claude Code Desktop puts a mode picker next to Send with names that state the consequence: Manual, Accept edits, Plan, Auto, Bypass permissions. The mode is remembered per folder, Plan applies only to the current session, and bypass must first be enabled in Settings. On the first action on a site it shows **Allow once / Always allow / Deny**. Computer-use access is tiered by app category (**View only / Click only / Full control**), with an extra warning for broad-reach apps and a Denied apps list. Some actions, such as archiving a session, **ask in every mode, including Bypass** ([Claude Code Desktop](https://code.claude.com/docs/en/desktop)). VS Code scopes approvals to this session, this workspace or always, and keeps them on one "Manage Tool Approval" screen ([VS Code trust & safety](https://code.visualstudio.com/docs/copilot/concepts/trust-and-safety)). The plan's §A already separates *open* from *interact* grants, which mirrors the View/Full split. The research suggests two additions. The first is a middle scope, **"Allow for this task"**, between Once and Always for this agent. That matches VS Code's session scope and avoids training the owner to click Always. The second is an explicit, published always-ask list (delete a world, close a running office, purchases, account creation) that no grant can cover.

One failure case should be written into the tests. Cursor's command-approval card carried an "Enable Auto-review" checkbox that was ticked by default, and **ticking it silently changed the global run mode**. Users called this a consent violation ([Cursor forum](https://forum.cursor.com/t/run-mode-not-respected-the-enable-auto-review-checkbox-changes-global-agentic-run-mode-and-violates-consent/163931)). An Ichos approval card must never change any setting beyond the grant it names. Cursor also documents allowlists and classifiers as best-effort guardrails, not security boundaries ([Cursor run modes](https://cursor.com/docs/agent/security/run-modes)). That supports keeping the taint gate as the real boundary. JetBrains calls its own Brave Mode "not recommended" ([Junie docs](https://junie.jetbrains.com/docs/junie-ide-plugin.html)). So DESIGN.md's "Full" permission chip should be gated behind Settings, as Claude's bypass is, and not offered as a casual composer toggle.

Visibility matters as much as permission. Copilot Vision draws a **glowing outline around anything the assistant can see** and puts Stop/X in the composer ([Microsoft Support](https://support.microsoft.com/en-us/microsoft-copilot/using-copilot-vision-with-microsoft-copilot)). The ChatGPT Atlas agent keeps **Take control** and **Stop** in a notification bar ([Simon Willison](https://simonwillison.net/2025/Oct/21/introducing-chatgpt-atlas/)). ChatGPT agent's takeover option sits under "…" and the agent **stops capturing screenshots while the user is in control** ([OpenAI Help mirror](https://help-lb.openai.com/en/articles/11752874-chatgpt-agent)). Kimi's agent shows a to-do list it ticks off item by item, along with its intermediate files ([MIT AI Agent Index](https://aiagentindex.mit.edu/2025/kimi-ok-computer)). Combined, these define one Ichos component. A window that a sub-agent is driving gets an AI-presence outline, the agent's name and avatar chip (already in §A), a checklist of steps, and visible **Take control · Pause · Stop** buttons. Logging pauses during takeover. In chat, the same run collapses to a compact card. Carbon's AI tokens give the outline a sanctioned recipe, re-coloured to the Ichos accent: an aura at accent 10 %, a border running from light accent at 36 % to solid accent, and accent-tinted skeletons at 30 % ([Carbon g100](https://cdn.jsdelivr.net/npm/@carbon/themes/src/g100.js)). The governing rule is Carbon's "do not use Carbon for AI styling as decoration" and Rovo's "applied to specific signifiers, not whole surfaces" ([Carbon for AI](https://carbondesignsystem.com/guidelines/carbon-for-ai/); [About Rovo UI](https://atlassian.design/rovo-ui/about-rovo-ui)). That is narrower than a blanket glow ban and more useful.

With an office full of agents, attention needs a budget. Warp groups alerts as **complete / request / error** (request means blocked on the user), caps corner toasts at **two** (hover pauses them, click jumps to the session), and backs them with a bell inbox filtered by All / Unread / Errors ([Warp notifications](https://docs.warp.dev/agents/capabilities/agent-notifications/)). VS Code's app-icon badge counts unread results, sessions waiting for input and failing CI ([VS Code chat sessions](https://code.visualstudio.com/docs/chat/chat-sessions)). Ichos should treat "waiting on you" as the loudest state (badge plus toast plus notch alert) and route everything else to the inbox. Messages between agents should arrive as attributed cards ("from Researcher", with a link back), delivered after the receiver's current step, with the receiver keeping its own permissions ([Claude Code Desktop](https://code.claude.com/docs/en/desktop)). For undo, Replit's checkpoints capture files, conversation and database with an AI summary, and **changes made after a rollback form a branch rather than being destroyed**. Windsurf's reverts are irreversible, which is the anti-pattern ([Replit checkpoints](https://docs.replit.com/core-concepts/agent/checkpoints-and-rollbacks); [Windsurf docs](https://docs.devin.ai/windsurf/plugins/cascade/cascade-overview)). GitHub links every agent commit back to its session log ([GitHub changelog](https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs)). Ichos can do the same for every window action.

The AI-UX guidelines turn this into rules. Every AI output carries a persistent AI label that also opens a short explanation, with more depth on request ([Carbon for AI](https://carbondesignsystem.com/guidelines/carbon-for-ai/)). PAIR asks that data sources be explained by **scope, reach and removal** ([PAIR](https://pair.withgoogle.com/chapter/explainability-trust/)). For a local-first app that popover is a selling point: "Ran on this PC with <model>; used these 3 memories; nothing left the device; forget them…". Confidence should appear only when it changes a decision, and then as categories or N-best alternatives rather than raw percentages ([PAIR](https://pair.withgoogle.com/chapter/explainability-trust/)). The accuracy caveat should be a persistent low-key line, never a modal ([HAX example](https://www.microsoft.com/en-us/haxtoolkit/example/copilot-in-outlook-g2-d-provide-low-performance-alerts/)). Memory retention works best as a plain choice, like Siri's "Keep Conversations: 30 days / 1 year / forever", and trivial commands should not be logged at all ([Engadget](https://engadget.com/2242748/how-to-use-the-new-siri-app-in-ios-27/)).

## Voice routines should be text-first, wake-gated and re-approved on every edit

Consumer routine builders all have the same shape: a trigger phrase, an ordered list of typed actions from a fixed menu, an explicit Wait step and a length cap. **Windows Voice Access, the closest same-platform precedent, offers exactly five action types and at most eight steps per shortcut**. You type or dictate the phrase in "When I say", and "Toggle <name>" enables or disables it ([Microsoft Support](https://support.microsoft.com/en-us/Accessibility/windows/voice-access/use-voice-to-create-voice-access-shortcuts)). Ichos's fixed step list in §C (open_app, open_path, open_url, open_window, set_layout, say, wait) fits this model. The eight-step cap is a sensible default. Leave out shell commands, keystrokes and mouse clicks at first, even though Windows offers them. Testing is weak almost everywhere. The best debugging aid found is Alexa's. **Voice History shows what the recognizer actually heard**, users copy that wording into the trigger, and a "Preview this action" button checks the response ([Amazon help](https://digprjsurvey.amazon.com/csad/help/node/GLXY7RFX3L5GH2VR)). Exact-phrase triggers break on paraphrase: an Alexa routine on "when is bedtime" did not fire for "what time is bedtime" ([Online Tech Tips](https://www.online-tech-tips.com/how-to-create-a-routine-with-amazon-alexa/)). Home Assistant's fix is cheap: allow several phrasings per trigger ([HA custom sentences](https://www.home-assistant.io/voice_control/custom_sentences/)).

This changes the plan's "say it 3 times" step. The plan stores the takes as a sound template *and* text. The evidence makes **typed text the source of truth**. The three takes then serve as a *recognizer-consistency check*: show "I heard: …" for each take, and offer to add any variant the recognizer produced as an alias. That builds Alexa's debugging loop into setup and needs no stored audio. Phrase design guidance points the same way. Phrases with fewer than six phonemes are not recommended, short words should get a prefix, and phonetically distinctive, low-frequency words cause "drastically fewer" misactivations ([Picovoice](https://picovoice.ai/docs/tips/choosing-a-wake-word/); [Sensory](https://sensory.com/custom-wake-words-branded-voice-ux-guide-2026/); [UVA thesis](https://libraetd.lib.virginia.edu/public_view/xs55mc908)). "Open up" and "warm up" are two short, common words each, and both occur in ordinary speech. The editor should lint phrases (phoneme count, common-word collisions, closeness to existing phrases and the wake word) and default every routine to `require_wake = true`. A bare phrase without the wake word should be an opt-in per phrase.

Confirmation follows Apple's model. Personal automations ask before running by default, and turning that off takes a second "Don't Ask" confirmation ([Apple Shortcuts guide](https://support.apple.com/guide/shortcuts/apd602971e63/ios)). The plan's "first run shows the steps and asks once" should be extended. Store a hash of the approved steps, and **require re-approval whenever the steps change**, so an edited routine cannot run unseen. No consumer system documents per-step risk confirmation. That is open design space, and the plan's taint gate fills it.

On the technology side, two licence facts change the options. **Picovoice's free tier stopped working on 30 June 2026**, and openWakeWord's pre-trained models are **CC BY-NC-SA** (non-commercial), even though its code is Apache-2.0 ([HA Community](https://community.home-assistant.io/t/fyi-picovoice-confirmed-free-tier-accesskeys-will-stop-working-after-june-30-2026/1012744); [openWakeWord](https://github.com/dscripka/openWakeWord)). The existing transcript-based wake match plus text-level phrase matching (normalise, exact or alias, then fuzzy with a per-phrase threshold) is the low-risk path. Vosk's runtime phrase lists work only on dynamic-graph models ([Vosk adaptation](https://alphacephei.com/vosk/adaptation)), and I did not verify the exact API. For speaking, barge-in should stop TTS after a few hundred milliseconds of user speech, and the client must flush queued audio itself. Hume's default minimum is 800 ms, adjustable from 50 to 2000 ([Hume interruptibility](https://dev.hume.ai/docs/speech-to-speech-evi/features/interruptibility)). Command matching should be suppressed while Ichos is speaking, so its own `say` lines cannot trigger routines. Gemini Live captions only its own speech ([9to5Google](https://9to5google.com/2025/06/25/gemini-live-android-captions/)). Ichos should caption both sides, because "what I heard" is the debugging tool.

## Where this research disagrees with the current plans

Most of DESIGN.md, DESIGN_FIX_PLAN.md and WINDOWS_IN_CHAT_PLAN.md hold up: chat first, windows summoned and owned by their chat, Recreate/Run again, one heavy window at a time, old tab ids kept as redirects, separate open and interact grants, and routines as data. The disagreements are concentrated in tokens and in a few defaults, so they are cheap to fix now and expensive after the Phase 0 token pass.

## Conclusion

The sweep moves Ichos's design question from layout to behaviour. Panes, popouts, notches and presets are commodity features now, and dockview supplies most of them. What remains hard, and where users have punished products, is *change*: layouts that reset or resize themselves, redesigns that keep moving the controls, and consent cards that quietly widen permissions. Ichos's real design system is therefore two sets of tokens. The visible set should come straight from Windows 11 so the app reads as native for free. The behavioural set is a matching vocabulary for agent grants, attention states, checkpoints and routine approvals, and each of those deserves the same rigour as a colour token: named, versioned, tested and reversible.

Two findings were surprising and should change near-term work. The accessibility target in DESIGN.md is already missed by its own proposed value, so the Phase 0 token pass should start from computed contrast rather than chosen hex values. And the owner's own environment shapes the defaults: the obvious notch hotkey already belongs to Claude Desktop, and the wake-word vendor most tutorials point to stopped offering a free tier this summer. A local-first assistant has to be designed around the machine it actually runs on.
